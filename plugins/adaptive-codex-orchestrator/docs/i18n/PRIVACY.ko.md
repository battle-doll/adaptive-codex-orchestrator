## 로컬 데이터 처리

제어 계층은 로컬·오프라인으로 동작합니다. 외부 네트워크 요청, 텔레메트리,
분석 서비스를 사용하지 않으며 API 키, OAuth 승인 또는 외부 계정이 필요하지
않습니다. Codex 호스트, 모델 제공자, 운영체제, Git과 저장소 제공자의 별도
동작에는 각자의 정책이 적용됩니다.

활성 파일 `${PLUGIN_DATA}/state-v1.json`에는 스키마 버전, 전체·프로젝트·세션·
한 번 범위의 모드/프로필 설정, SHA-256 프로젝트 키, 세션 식별자, 수명주기
플래그와 정리에 필요한 제한된 last-seen 값만 들어갑니다. 프로젝트 해시는
안정적인 가명 식별자이지 암호화가 아니며 후보 경로를 아는 사람은 다시 계산할
수 있습니다.

세션에는 같은 간결한 정책의 반복 전달을 막는 제한된 숫자형
`active_policy_revision` marker도 저장되며, 프롬프트나 작업 내용은 담지 않습니다.

런타임은 잠금 파일, 원자적 쓰기 임시 파일, 읽을 수 있는 손상 상태의 content-
addressed 백업도 만들 수 있습니다. 다른 프로세스가 손상 파일에 임의 바이트를
넣었을 수 있으므로 백업은 민감한 로컬 증거로 취급하세요. 플러그인은 이를
해석하거나 전송하지 않습니다.

프롬프트, 대화 기록, 소스 코드, 패치, 원본 절대 프로젝트 경로, 저장소 이름,
자격 증명, 모델 출력, 작업자 대화, 검증 로그, 텔레메트리나 광고 식별자를
저장하지 않습니다. 프롬프트는 현재 이벤트의 메모리에서만 파싱됩니다.

한 번 상태는 요청 완료 후 지워집니다. 세션 상태는 호스트의 세션 종료 이벤트로
지우며, 이벤트 누락에 대비해 비활성 상태가 **30일**을 넘은 세션 항목도 이후
`SessionStart`에서 제거합니다. 프로젝트와 전체 설정은 변경하거나 초기화할
때까지 유지됩니다.

## 안전한 초기화

관련 세션을 끝낸 뒤 `adaptive-codex-orchestrator`에 할당된 정확한
`PLUGIN_DATA` 경로를 확인하고 해석하세요. 플러그인 전용 데이터 폴더이며
플러그인 소스, 저장소 루트, 홈, `.codex` 루트 또는 공유 상위 폴더가 아님을
검증한 뒤 그 폴더만 삭제합니다. 복구 자료를 남기려면 `state-v1.json`만
삭제합니다. 와일드카드, 해석되지 않은 환경 변수, 홈 또는 공유 상위를 재귀
삭제 대상으로 사용하지 마세요.

향후 네트워크, 텔레메트리, 자격 증명, 프롬프트·소스 저장, transcript 접근,
새 식별자나 수신자를 추가하려면 명시적 정책 갱신, 보안 검토, 사용자 고지,
버전 상태 처리와 필요한 동의가 선행되어야 합니다.

제어 명령은 한국어와 영어만 인식합니다. 번역 문서는 일본어·중국어·러시아어
명령 지원을 추가하지 않습니다.
